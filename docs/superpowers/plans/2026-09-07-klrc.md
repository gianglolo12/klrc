# klrc Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CLI cho macOS phát nhạc từ link YouTube hoặc file local và chạy lời bài hát tô sáng từng chữ theo nhạc, kèm slash command `/karaoke` cho Claude Code.

**Architecture:** Sáu module độc lập nối bằng kiểu dữ liệu rõ ràng: `resolver` biến input thành `Track`, `lyrics` lấy `.lrc` từ LRCLIB rồi nội suy timing từng chữ, `audio` phát nhạc sau một interface `Player` và tính trước spectrum bằng FFT, `ui` là hàm thuần `(state, positionMs, width) -> string` chạy trong vòng lặp 30fps. Vì `ui` chỉ đọc `player.positionMs`, một `Player` giả biến toàn bộ animation thành thứ test được bằng snapshot.

**Tech Stack:** Node.js 24 + TypeScript (native type-stripping, không cần tsx/ts-node), `node:test` built-in (không cần vitest/jest), `ffmpeg-static`, `music-metadata`, và yt-dlp standalone tự quản (không qua npm — xem phát hiện 6). FFT tự viết (~40 dòng) để không thêm dependency.

**Spec:** `docs/superpowers/specs/2026-09-07-cli-karaoke-design.md`

1. **LRCLIB không có enhanced LRC.** Đã thử nhiều bài phổ biến (Ed Sheeran, Sơn Tùng, <nghệ sĩ>): 100% chỉ có timing theo dòng. import { test } from 'node:test'
```ts
import assert from 'node:assert/strict'
import { interpolateWords } from './interpolate.ts'
import type { Line } from './types.ts'

const line = (text: string, startMs = 0, endMs = 4000): Line =>
  ({ text, startMs, endMs, words: [] })

test('chia thời gian theo độ dài từ, không chia đều theo số từ', () => {

  assert.deepEqual(interpolateWords(pre), pre.words)
```

- [ ] **Step 3: Viết `src/lyrics/interpolate.ts`**

Thuật toán — **chia theo trọng số độ dài từ, không chia đều**:

1. Nếu `line.words.length > 0` trả về luôn.
2. `tokens = line.text.trim().split(/\s+/).filter(Boolean)` (rỗng -> `[]`).
3. Trọng số mỗi từ: `weight = token.length + 1` (cộng 1 mô phỏng khoảng nghỉ giữa các từ, và để từ 1 ký tự không bị quá nhanh).
4. `total = sum(weights)`; `span = max(line.endMs - line.startMs, 0)`.
5. Rải liên tiếp: `cursor = line.startMs`, mỗi từ `dur = max(round(span * weight / total), 60)`, `startMs = cursor`, `endMs = cursor + dur`, `cursor = endMs`.
6. Ép từ cuối `endMs = line.endMs` **chỉ khi** `line.endMs >= cursor` (giữ liền mạch mà không co lại âm).

Vì sao trọng số theo độ dài chứ không chia đều: chia đều làm từ "a" sáng lâu bằng từ "wonderful", nhìn là thấy sai nhịp ngay. Độ dài ký tự là xấp xỉ rẻ và đủ tốt cho số âm tiết.

```ts
  frames: Array.from({ length: 100 }, () => Uint8Array.from({ length: 16 }, (_, i) => i * 16)),
}

test('dài đúng width yêu cầu', () => {
  for (const w of [16, 40, 80]) {
    assert.equal(stripAnsi(spectrumLine(sp, 1000, w)).length, w)
  }
})

test('vượt quá cuối bài trả dòng trống cùng độ dài', () => {
  const out = stripAnsi(spectrumLine(sp, 999999, 40))
  assert.equal(out.length, 40)
  assert.equal(out.trim(), '')
})

test('vị trí âm cũng trả dòng trống, không nổ', () => {
  assert.equal(stripAnsi(spectrumLine(sp, -500, 40)).length, 40)
})

test('không có frame nào thì không nổ', () => {
  const empty = { frameMs: 50, bands: 16, frames: [] }
  assert.equal(stripAnsi(spectrumLine(empty, 0, 20)).length, 20)
})

test('width nhỏ hơn số dải vẫn ra đúng độ dài', () => {
  assert.equal(stripAnsi(spectrumLine(sp, 1000, 8)).length, 8)
})
```

`spectrumLine`: `idx = Math.floor(positionMs / frameMs)`; ngoài phạm vi hoặc `frames` rỗng → `' '.repeat(width)`. Trải `bands` dải ra `width` cột (cột `i` lấy dải `floor(i * bands / width)`), mỗi cột chọn ký tự trong `' ▁▂▃▄▅▆▇█'` theo giá trị 0-255.

- [ ] **Step 3: Viết `mpv-player.ts`**

`spawn('mpv', ['--no-video', '--no-terminal', '--input-ipc-server=' + sock, path])`, `sock = join(tmpdir(), 'klrc-mpv-' + process.pid + '.sock')`.

Kết nối `net.createConnection(sock)` với thử lại: mpv cần ~100-300ms để tạo socket, nên thử tối đa 30 lần cách nhau 50ms rồi mới bỏ.

Giao thức: mỗi lệnh là một dòng JSON `{"command":["get_property","time-pos"],"request_id":N}`; phản hồi cũng là một dòng JSON, khớp bằng `request_id`.

`positionMs` — **không hỏi socket đồng bộ trong vòng lặp render** (sẽ chặn 30 lần/giây). Thay vào đó: một `setInterval` 250ms hỏi `time-pos` rồi hiệu chỉnh mốc `baseMs`/`baseAt`; getter nội suy `baseMs + (Date.now() - baseAt)`. Vừa mượt vừa không lệch tích luỹ — đây chính là lý do chọn mpv.

`pause()`/`resume()`: `set_property pause true|false`. `seek(ms)`: `["seek", ms / 1000, "absolute"]` rồi cập nhật ngay `baseMs = ms`. `stop()`: gửi `quit`, đóng socket, `unlink` sock (bọc try/catch), kill process nếu còn. `onEnd`: mpv thoát mà không do `stop()` → gọi callback.
